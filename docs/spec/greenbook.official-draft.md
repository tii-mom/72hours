## 0. 先把边界说清楚

72H 不是“看价格等涨”的故事，也不是“点一下就发钱”的空投项目。

72H 想做的是：用一个固定供应的代币，把真实产品使用、72 小时赛季玩法、战队协作、邀请传播、学习成为开发者这几件事连接起来，让普通加密用户不再只是围观，而是能真正进入项目、理解项目、参与项目，最终有机会成为建设者。

同时，必须把边界放在最前面：

- 没有固定收益
- 没有无风险收益
- 没有保证领取
- 存入并锁定不等于保证获得奖励
- “通往财富自由之路”是产品愿景名称，不是财富自由承诺
- 本文不构成投资建议、法律建议或收益承诺

72H 的强叙事不应该建立在承诺收益上，而应该建立在使用、参与、学习和可验证规则上。

## 1. 你是不是也厌倦了“看客”的身份？

很多普通用户进入加密世界后的日常，是这样的：

- 每天打开行情软件，盯着红绿跳动的数字
- 加了无数个群，等公告、等利好、等别人喊单
- 看着别人链上交互，自己不知道从哪里开始
- 看着别人拿到身份、排名、机会，自己永远慢半拍
- 项目越来越多，信息越来越乱，最后只剩下猜和赌

这不是一个人的问题，而是加密行业长期存在的问题。

很多加密产品默认服务的是“已经懂的人”。他们懂钱包、懂链上交互、懂合约、懂规则、懂怎么参与早期生态。但普通用户站在门外，看着里面灯火通明，却找不到门把手。

围观很容易，真正进入很难。

72H 想做的，就是那个门把手。

它不只是让你买一个代币放在钱包里，也不是让你继续等下一条消息。72H 要给普通用户一条更清晰的路径：

```text
看项目的人 -> 参与项目的人 -> 学习项目的人 -> 建设项目的人
```

这就是 72H 绿皮书要讲的故事。

## 2. 72H 是什么？

72H 是一个已在 TON 主网发行的固定供应代币，也是 72hours 生态的统一入口。

公开合约信息显示：

- 总量：`100,000,000,000 72H`，也就是 1000 亿枚
- `mintable = 0`，不能继续增发
- `admin = null`，没有管理员增发后门

翻译成人话：

> 没有人可以再凭空印出新的 72H，包括团队自己。

这很重要。因为在加密世界里，普通用户最怕的不是价格波动，而是自己手里的资产被无声稀释，规则被后台改写，供应被随意扩张。

72H 的第一层信任，来自固定供应。

但 72H 不只是一个“发了币等上涨”的项目。它是一套系统：用一个固定供应的代币，把真实产品、赛季玩法、战队协作、邀请传播和建设者学习路径连成一条路。

一句话：

> 72H 是普通加密用户进入加密应用世界的行动入口。

## 3. 为什么 900 亿是核心？

72H 总量为 `100,000,000,000 72H`，主要分配如下：

| 模块 | 数量 | 说明 |
| --- | ---: | --- |
| 赛季玩法池 | `90,000,000,000 72H` | 72H 的核心玩法库存，占总量 90% |
| 预售池 | `4,500,000,000 72H` | 用于早期发行与市场启动 |
| 生态池 | `4,500,000,000 72H` | 用于生态应用、合作与后续激励 |
| 开发基金 | `500,000,000 72H` | 用于产品、工具、基础设施和学习支持 |
| 团队释放 | `300,000,000 72H` | 团队激励，按阶段释放规则执行 |
| 早期用户与运营 | `200,000,000 72H` | 用于早期用户和运营活动 |

你需要抓住一个重点：

> 900 亿 72H 不在一句口号里，而在赛季玩法池里。

这意味着，72H 最大的一部分供应，不是只拿来讲故事，而是被设计成围绕用户参与、赛季节奏、战队协作和公开名单运转的玩法库存。

900 亿的意义，不是“人人瓜分”，也不是“一次发完”。

它的意义是：给普通用户一个长期、可参与、可重复、可验证的入口。

## 4. 900 亿赛季玩法池：不是空投，是赛季库存

72H 的 900 亿玩法池，被设计为最多 10 个赛季，每个赛季 18 轮，每轮对应 `500,000,000 72H` 的玩法库存。

```text
90,000,000,000 72H
= 10 个赛季 x 18 轮 x 500,000,000 72H
```

这带来一个重要变化：

> 用户不是在等一波空投，而是在进入一套有节奏、有轮次、有成败、有规则的赛季系统。

每个轮次不是自动发放。轮次会有结果：

### 成功轮次

当一轮满足公开规则并通过后续流程时，对应的 72H 会进入用户领取路径：

```text
SeasonVault -> SeasonClaim -> 用户钱包
```

也就是说，成功轮次的玩法库存会进入可领取池，之后符合条件的用户可以按公开名单和验证流程领取。

### 失败轮次

当一轮没有满足规则时，对应的 72H 不会进入用户领取池，也不会变成随意发放的奖励，而是进入 FundVesting 等后续规则处理路径。

这句话非常关键：

> 不是“开了就一定发”，而是“符合规则、通过验证、进入名单，才可能领取”。

这套设计的目标，是让玩法可以热闹，但资金路径必须清楚；让社区可以有冲刺感，但真实奖励必须回到规则、链上记录和平台核对。

## 5. 每个成功轮次的 5 亿 72H 怎么分？

每一个成功轮次，对应 `500,000,000 72H`。分配方向如下：

| 分配方向 | 比例 | 数量 |
| --- | ---: | ---: |
| 个人有效存入 | 50% | `250,000,000 72H` |
| 战队存入 | 25% | `125,000,000 72H` |
| 邀请 / 新用户 | 15% | `75,000,000 72H` |
| 排行榜 | 10% | `50,000,000 72H` |

这四个方向，分别对应四种真实行为：

- 你自己的真实参与：有效存入并锁定
- 你和别人一起行动：加入 Squad 战队
- 你带新人做正确动作：邀请真实用户完成有效参与
- 你在公开规则里竞争：排行榜、战绩、身份和记录

72H 不奖励空转热度，不奖励无意义点击，也不奖励伪造参与。

真正有意义的是：用户是否完成了可验证的动作。

## 6. 领取不是“点一下就有”

为了避免机器人、女巫攻击、刷量、虚假邀请和伪造参与，72H 的领取必须依赖一组条件链。

真实领取资格至少需要考虑：

- 已验证钱包
- 链上确认的有效锁仓
- 风控审核
- 去重规则
- 排行榜规则与校验
- 公开名单
- 对应轮次是否成功
- 对应领取阶段是否开放

因此，72H 对外应该使用准确口径：

> 72H 的赛季奖励是基于规则的资格制领取，不是人人可领，也不是存了就一定有。

这套机制看起来更严格，但它保护的是认真参与的用户。

因为在一个真实的开放系统里，如果没有风控，最后拿走奖励的往往不是普通用户，而是脚本、刷子和羊毛团队。

72H 要保护的，是愿意真实上场的人。

## 7. 通往财富自由之路：不是承诺，是行动路径

72H 的外部产品路径，建议统一称为：

> 通往财富自由之路

这个名字必须解释清楚。

它不是财富自由承诺，不是收益保证，也不是一句刺激用户冲动存入的话术。

它表达的是一条行动路径：普通用户从围观项目开始，进入 72 小时赛季，通过真实动作证明参与，在战队、邀请和排行榜中形成身份，并在学习路径中逐步理解如何建设加密应用。

这条路可以分成三段：

### 第一段：低门槛进入

用户不需要一开始就理解所有合约细节。

他们可以先领取 Rush Pass，进入一个 72 小时波次，获得自己的入场身份、邀请入口和传播内容。

但必须明确：

> Rush Pass 不是资产，不是空投承诺，不代表收益。

它的意义是入口与身份，不是钱。

### 第二段：用链上动作证明参与

真正的参与，不是转发海报，不是进群喊口号，也不是点击按钮。

在 72H 的赛季系统里，有效存入并锁定，是用户进入真实计算的重要动作。

这一步让用户从“看项目的人”，变成“在项目里留下记录的人”。

### 第三段：在协作与竞争中形成身份

用户可以加入 Squad 战队，和其他人一起冲刺。

战队带来的不只是排名，还有社会压力、协作关系和荣誉感。你会看见队友的行动，看见头部战队的打法，看见自己和别人之间的差距。

排行榜不是为了制造焦虑，而是为了让路径变得可见：

- 谁在参与
- 谁在带新人
- 谁的战队在增长
- 谁的动作更有效
- 谁真正理解了玩法

72H 希望把看不见的参与，变成看得见的身份。

## 8. 真实使用场景：WAN

72H 不应该只存在于交易和叙事里。

WAN 是 72H 的真实使用场景之一。WAN 是 Web-first 控制台，原生端保留 VPN 服务和 72H 充值等关键能力。

在 WAN 里，72H 可以承载这些价值点：

- 作为真实服务入口
- 与 VPN、流量卡、充值路径相关联
- 普通钱包每月可获得基础流量权益，按产品规则执行
- 持有 72H 可对应流量卡权益规则，例如 `100,000 72H -> 20GB card`，并受上限、风控和具体规则约束

这说明 72H 不只讲“未来想象”，也在连接真实产品。

但这里同样需要明确：

> 服务权益属于产品规则，不是金融收益承诺。

一个健康的代币生态，不能只靠口号维持。它需要真实入口、真实使用和真实场景。

WAN 就是 72H 的现实入口之一。

## 9. Season War：让赛季变得可见

Season War 是 72H 赛季玩法的展示与导航层。

它适合展示：

- 当前赛季状态
- 倒计时
- 轮次信息
- 排行榜
- 可领取估算
- 入口跳转
- 用户当前所处位置

Season War 的价值，是让复杂的赛季系统变得可读、可追踪、可期待。

但必须明确：

> Season War 不是最终奖励记账来源。

最终结算依赖链上模块、有效参与记录、风控审核、去重规则和公开名单。

Season War 是窗口，不是账本。

## 10. 从用户到建设者

72H 最长期的目标，不是让更多人永远停留在“买币等待”的状态。

72H 更希望发生的是：一部分普通用户，在一次次产品使用、赛季参与、战队协作、规则理解和学习训练中，逐渐学会建设加密应用。

路径可以这样理解：

```text
普通用户
  -> 进入产品，理解 72H 可以怎么用
参与者
  -> 进入赛季，理解锁仓、战队、邀请和排行榜
学习者
  -> 理解钱包、页面、合约规则、风控和名单
建设者
  -> 通过线上和线下学习，尝试做自己的加密应用
生态贡献者
  -> 参与 72H 生态应用、工具、组件和增长建设
```

这也是 72H 和很多项目不一样的地方。

很多项目的终点，是让你持有。72H 更希望让一部分用户学会判断、学会拆解、学会构建。

因为在加密行业里，真正长期改变命运的，往往不是只会买卖，而是理解系统如何运转，并能参与建设。

72H 想把普通用户带到这条路上。

## 11. 为什么这套规则值得被认真看待？

加密世界从来不缺故事。

真正稀缺的是可验证的秩序。

72H 选择把几个关键点公开：

- 供应固定
- 不可增发
- 无管理员增发权限
- 900 亿进入赛季玩法池
- 成功轮次和失败轮次路径不同
- 成功轮次按 50 / 25 / 15 / 10 拆分
- 领取依赖公开规则、链上记录、风控审核和名单

这些设计的意义，是让用户在参与前能判断：

- 供应是不是可预期
- 规则是不是能解释
- 奖励是不是有条件
- 风控是不是存在
- 路径是不是透明

72H 要讲的不是“相信我们”，而是“先看规则，再决定是否参与”。

Rush Pass 是入场与传播入口，不是资产，也不是收益凭证。

一个人很容易放弃，一群人更容易形成节奏。战队、排行榜、邀请和身份卡，会帮助用户更快理解玩法。
