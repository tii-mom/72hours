# 72hours Green Book

Last updated: 2026-04-22

## 摘要

72hours 是由技术开发者创建的社区和生态入口，面向非技术用户。它不以协议创新为中心，而以代币使用场景、应用参与机制和商业模式为中心。`72H` 是生态通证，是用户进入 72hours 的统一入口。

## 1. 持有 `72H` 能获得什么

持有 `72H` 的意义不是治理，而是进入生态的使用权与参与权。持有者可以：

- 使用 72hours 所有产品和服务
- 参与 72hours 内应用的支持、认购和早期参与
- 参与 72hours 推出的 Vibe coding 学习与加密应用开发
- 获得生态活动、贡献激励和优先资格

`72H` 是 utility-first token，不是 governance token。

## 2. `72H` 的三大使用场景

### 2.1 使用产品和服务

`72H` 用于支付 72hours 生态内的产品和服务。用户使用 `72H` 不是为了囤积，而是为了进入真实场景。

### 2.2 参与应用投资与早期支持

72hours 内的应用会分为不同阶段。用户可以参与更稳健的成熟应用支持，也可以参与更高风险的种子轮机会。不同项目对应不同风险等级与信息披露标准，不提供收益保证。

### 2.3 学习和开发

`72H` 也是学习入口。用户可以用它进入 Vibe coding 路径，学习如何用 AI 工具和模板参与加密应用开发，从使用者变成建设者。

## 3. 商业模式

72hours 的商业模式来自四部分：

- 产品和服务收入
- 应用上架、孵化和投资
- 学习路径、训练营和开发支持
- 生态合作与分发

我们不依赖单一的内容叙事，也不依赖技术卖点。我们依赖代币使用、应用参与和学习转化形成的真实需求。

## 4. 供给模型

`72H` 总供应量固定为 `100,000,000,000`，不增发。公开账本分桶为：

- `4,500,000,000 72H`：Sale Pool
- `4,500,000,000 72H`：House Vault
- `500,000,000 72H`：LP Reserve
- `500,000,000 72H`：Core Growth Reserve
- `90,000,000,000 72H`：Shadow Supply

供应固定，不通过增发扩张。各保留桶的释放规则另行公布。

## 5. 边界

- `72H` 不承担治理权
- 参与生态不等于收益保证
- 项目机制可能随阶段更新
- 本文不构成投资建议

## 6. 目标

让持有 `72H` 变成进入产品、参与应用和学习开发的统一动作，让使用、参与和商业循环连在一起。
