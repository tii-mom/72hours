# 72hours Green Book

Last updated: 2026-04-28

## Abstract

72H is not a token that only asks people to watch a chart and wait for news.

72H is not a chart story. It is a path for ordinary people entering the crypto world.

That path starts with real products, moves through the 90B game pool and 72-hour seasons, enters the Road to Financial Freedom through teams, invites, and leaderboards, and finally helps some ordinary users become builders.

The key change is simple: 72H is not only telling a story. It connects fixed supply, the `90,000,000,000 72H` game pool, valid deposits and locks, team play, invite growth, and online/offline learning into one path.

72hours is built for ordinary crypto users: people who can buy tokens, join communities, and follow projects, but have not yet had a clear path to participate in crypto application building.

The 72H story is simple:

- Use it: enter real products and services
- Play it: make a valid deposit and lock inside the Road to Financial Freedom, then join 72-hour seasons, teams, invites, and leaderboards
- Build with it: learn with AI-assisted tools and move from user to crypto application developer

72H is issued on TON with a fixed total supply of `100,000,000,000 72H`. The key point is simple: the total supply is fixed and no more 72H can be created.

`90,000,000,000 72H` is the 72-hour season game pool. It gives the story weight and gives ordinary users a clear target: participate through real actions and compete for claim eligibility under public rules. If a round does not qualify, or if a user does not pass checks, it should not be treated as an already claimable reward.

This document is not investment advice and does not promise returns. It explains how 72H can be used, how the gameplay works, how people can learn, and what boundaries must stay clear.

The 72H design is not about voting language or complex financial terms. It puts the token into real actions:

- use 72H to enter products and services
- use 72H to participate in ecosystem applications
- use 72H to enter 72-hour gameplay
- use 72H inside the Road to Financial Freedom to make a valid deposit and lock, then enter real season calculation
- use 72H to apply for learning and developer training

The total supply is fixed at `100,000,000,000 72H`, with several clear uses:

- `90,000,000,000 72H`: season game pool for 72-hour gameplay, moved by public rules into claim or locked pools
- `4,500,000,000 72H`: presale pool
- `4,500,000,000 72H`: ecosystem pool for applications and future incentives

The point is not to make the allocation table look complicated. The point is to give each part of the supply a clear job. 72H turns holding a token into a chain of real actions: entering products, making a valid deposit, joining seasons, forming teams, and learning to build.

## 2. Why The 72H Gameplay Is Different

72H does not want users to read a story and then wait for price movement. 72H wants users to enter a visible system.

### 2.1 90B Season Game Pool

`90,000,000,000 72H` is placed into the game pool for 72-hour seasons.

This is not only a large number for a poster. It gives users a feeling that there is a real system here, built around time, action, teams, and public rules.

The gameplay can be understood simply:

- one round lasts `4` hours
- one season has `18` rounds
- there can be up to `10` seasons
- each round uses a fixed `500,000,000 72H`

If a round meets the public rules, that round's 72H moves into the user claim pool. Users on the public list can later claim.

If a round does not meet the rules, that 72H does not go to an admin wallet. It moves into a locked pool and waits for later handling under public conditions.

This design tries to solve one problem: the game can be active, but the token path must stay clear. Users see a 90B game pool, but whether they can claim depends on public rules, on-chain records, public list records, and platform checks.

### 2.2 Valid Deposits, Teams, And Leaderboards

Ordinary users do not need to understand every technical detail on day one. They can start with simple actions:

- claim a 72-hour entry pass
- join a team
- invite friends
- follow a leaderboard
- generate and share an identity card
- if they want to enter real season calculation, make a valid deposit and lock

One boundary matters: activity is only activity. It is not the same as a real token reward.

Whether someone can receive a real reward depends on public rules, on-chain records, public list records, and platform checks. This lets the community spread while keeping reward promises out of normal sharing or a single deposit.

The Road to Financial Freedom does not mean a deposit automatically creates an outcome. The name expresses a direction and a vision, not a promised result. Its real job is to turn watching into action: users prove real participation through on-chain deposits and locks, then enter 72-hour seasons through teams, invites, and leaderboards.

### 2.3 From Watching Projects To Entering Projects

Many projects only ask users to watch the story. 72H asks users to enter real scenarios:

- use 72H inside WAN
- join 72-hour gameplay through Season War
- make a valid deposit and lock inside the Road to Financial Freedom, then understand teams, invites, and leaderboards
- understand stages, seats, risk, and verification through application seat pages

Users do not understand 72H only by listening to explanations. They build judgment through repeated use and participation. Real trust is not printed on a poster; it grows after users connect wallets, join teams, see rules, and understand the flow.

## 3. How Ordinary Users Can Learn To Become Developers

The long-term goal of 72H is not to keep users buying and waiting. It is to help some ordinary users learn to build.

The hardest barrier in crypto is often not a technical word. It is that ordinary users do not know where to start. 72H breaks that entry down: understand wallets, understand pages, understand rules, and then understand why an application can run.

Through online and offline AI-assisted building, ordinary users can learn:

- how wallets connect
- how applications interact with TON
- how a frontend page shows product status
- how entry passes, teams, leaderboards, and share cards are designed
- why public lists, claim rules, and platform checks matter
- how to use AI tools and templates to make a crypto application prototype

This is not a course dressed up as a project, and it does not make everyone an expert overnight.

A more realistic path is:

```text
ordinary user -> participant -> helper -> application developer
```

Use first. Participate next. Break down how it works. Then try to build. 72H is not trying to produce better spectators; it wants some ordinary users to develop the feel of builders.
