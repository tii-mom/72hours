# 72hours Green Book

Last updated: 2026-04-22

## Abstract

72hours is a community and ecosystem entry point built by technical developers for non-technical users. It is not centered on protocol innovation. It is centered on token utility, application participation, and the commercial model. `72H` is the ecosystem token and the unified interface for entering 72hours.

## 1. What Holding `72H` Gives You

Holding `72H` is not about governance. It is about access and participation. Holders can:

- use all 72hours products and services
- participate in support, subscription, and early access for in-house applications
- join Vibe coding learning and crypto application development
- receive ecosystem activity access, contribution incentives, and priority eligibility

`72H` is utility-first, not governance-first.

## 2. The Three Core Use Cases

### 2.1 Products and Services

`72H` is used to pay for products and services inside the 72hours ecosystem. Users spend `72H` to enter real usage, not to sit on a speculative balance.

### 2.2 Application Investment and Early Support

In-house applications move through different stages. Users can support more mature applications through a steadier path, or join higher-risk seed-stage opportunities. Risk levels and disclosure standards differ by project, and no return is guaranteed.

### 2.3 Learning and Building

`72H` is also a learning entry point. Users can use it to enter the Vibe coding path and learn how to use AI tools and templates to build crypto applications, moving from user to builder.

## 3. Business Model

72hours' business model comes from four sources:

- product and service revenue
- application listing, incubation, and investment
- learning paths, training, and builder support
- ecosystem partnerships and distribution

We do not rely on abstract narratives or technical claims. We rely on real demand created by token usage, application participation, and learning conversion.

## 4. Supply Model

`72H` uses a fixed-supply model with a total supply of `100,000,000,000`. The documented buckets are:

- `4,500,000,000 72H`: Sale Pool
- `4,500,000,000 72H`: House Vault
- `500,000,000 72H`: LP Reserve
- `500,000,000 72H`: Core Growth Reserve
- `90,000,000,000 72H`: Shadow Supply

The supply is fixed and does not expand through minting. Release rules for reserve buckets are announced separately.

## 5. Boundaries

- `72H` does not carry governance rights
- participation does not guarantee returns
- project mechanisms may change by stage
- this document is not investment advice

## 6. Goal

The goal is simple: make holding `72H` the common action for entering products, participating in applications, and learning to build, so usage, participation, and the commercial loop stay connected.
